# HAW-75 refused-row activation acceptance

Status: inactive local diagnostic component and unimplemented integration acceptance, 19 November 2026. The published selector at `ccd5c33fe1e045749f2919ada67959b6411ccaf9` safely refuses oversized or invalid pages. Its component CI and direct Claude review passed; neither proves how a tenant resumes when its first unresolved row is permanently refused. The new local diagnostic read described below has no physical execution proof, durable store, resolver, production caller, cursor or policy change. This document keeps the activation blocker explicit.

## Existing proof and the remaining blocker

The [selector](../src/tenants/m365-audit-gap-selection.ts) exposes only fixed refusal codes. An oversized first row returns no row identity, descriptor, candidate or continuation. The [physical suite](../src/tenants/m365-audit-gap-transfer.database-integration.test.ts) proves refusal and preservation of the source and populated coverage state, including a later valid row; it does not prove eventual progress past that first row. The [transfer helper](../src/tenants/m365-audit-gap-transfer.ts) needs a complete lossless descriptor including the exact URI. It cannot consume a refusal, a row ID alone or a truncated URI.

Two obligations must both pass before integration: preserve coverage evidence under refusal, and durably resolve or safely classify the exact blocking source so a later page can progress. Retrying forever satisfies only the first. A diagnostic record, a shorter error message or an increased limit cannot by itself satisfy the second. Until executable proof exists, keep the production caller absent and the blocker open.

The [selection contract](haw75-gap-selection-contract.md), [transfer/reader contract](haw75-gap-transfer-reader-contract.md) and [recovery order](haw75-gap-recovery-order.md) continue to govern cursor, ownership, evidence retention, outcomes and competing writes. This is not a substitute for HAW-21's real owner fence or HAW-77's outcome rules.

## Diagnose a source without transporting its payload

A future diagnostic read must be a separate bounded, scoped database projection; it must not fetch the rejected page and then redact it. It must distinguish source-specific evidence from a failed or untrustworthy transport. Proposed fields are internal organization/tenant/ledger IDs, a fixed reason, bounded validation flags and an observation time. Lengths, if needed, must be bounded/saturated metadata with an explicit overflow flag. No provider URI, raw content ID, payload, serialized row, raw driver error or URI-derived digest belongs in diagnostics, logs or API output. IDs and any eventual durable diagnostics remain tenant-authorized and must not become a new public read surface.

The projection selects the same logical first unresolved row using the original scope and continuation. It is a new observation, not proof that this row caused a previous refusal: a concurrent insertion or change can replace that first row. Bind any later action to the freshly revalidated source, never retrospectively attach the old error to a guessed row. A revision timestamp by itself is not an exact claim; existing direct writers need not have advanced it. Preserve the full selected-field comparison or prove an equivalent server-side identity/revision contract across every writer without returning the oversized URI.

| Failure observed | Diagnostic meaning and required handling |
| --- | --- |
| URI or serialized-page limit | Diagnose the current scoped row without returning its URI/page. The independent URI and full serialized-page gates remain enforced. A later resolver still needs exact source validation. |
| Invalid source fields | Report only fixed validation flags from a trustworthy bounded read. Do not invent a content identity, normalize malformed evidence or classify an invalid deadline as expired. |
| Invalid result, parser failure, query failure or unsupported encoding | The transport may not establish any source identity. Do not create a row-level resolution based on that error. Preserve the last committed pass position and incomplete outcome; an encoding/adapter fix is a separate qualified change. |
| No row on a later diagnostic read | Absence is not successful resolution. Require the matching committed terminal evidence or a safely ended removed scope before any progress claim. |

A future durable diagnostic must survive process restart, remain scope-bound and idempotent for the chosen observation identity, and retain unresolved state until resolution is proved. Its schema, uniqueness/versioning, access controls, bounded growth and retention are deliberately undecided. No new diagnostic retention period, retry cadence, attempt counter or failure classification is selected here. Adding that store alone must not change source status, refresh gap retention or allow a successful visit outcome. If recording it fails, preserve the prior cursor and fail closed; do not label the source diagnosed durably.

## Resolution requirements, with no bypass

The following are acceptance routes to qualify, not implemented recovery procedures or permission to repair production manually.

1. **A valid source that exceeds the projection envelope.** A future server-side path may transfer the same valid expired source without exporting its URI, but it must prove exact scoped identity and all claim fields under the common tenant/state/gap/source serialization. Recheck real ownership and database expiry after waits. Gap, sticky state, exact source removal and coherent visit outcome must commit atomically; retention, identity conflicts, overflow and accounting retain the existing contract. No partial projection may be passed to the current helper. This requires a separately reviewed implementation and actual-writer race proof; it is not granted by today's selector tests.
2. **A source legitimately changed by an authorized writer.** Re-read it through the bounded selector if it fits and apply the normal exact-current-source rules. If the fresh row is still oversized, re-diagnose it and require the separately qualified server-side route; a failed bounded re-read supplies no continuation. The diagnostic does not authorize an edit, force retry, URI truncation, status rewrite or deadline extension. A new valid expired descriptor can transfer; a valid not-expired row may be revisited on the next pass under the durable cursor contract. Changed fields alone do not establish completion. Include a fresh positive control so rejecting every changed row cannot masquerade as a solution.
3. **A source now absent or completed.** Verify the precise committed gap plus sticky state, or the matching completed checkpoint/accounting proof, under the shared scope and identity contract. A diagnostic ID, a staged transfer result, a changed/absent return code or a successful query is insufficient. Unknown commit results require re-reading the durable effects before recording resolved status or advancing the pass.
4. **An invalid or conflicting source with no valid transfer identity.** Preserve it and incomplete coverage. This design defines no automatic correction or deletion. Identify and separately qualify a supported reconciliation mechanism before activating a system that can encounter that class. A release matrix must enumerate supported source/encoding classes and either prove a safe resolution for each or explicitly retain the activation hold; an assertion that current discovery usually emits valid rows does not exclude legacy/direct-written rows.

Resolution of a diagnostic does not clear a sticky coverage marker or prove recollection. A safe gap transfer allows ledger progress while preserving the incomplete coverage fact. Diagnostic completion, pass progress and any required visit outcome must share a proven atomic or recoverably idempotent commit contract; a crash between them must never report unprocessed evidence as complete. Neither a durable diagnostic nor a separate gap marker permits skipping a still-unresolved source.

The future integrated pass must remain stopped before a refused row whose exact safe disposition is unproved; moving the cursor past that row, changing its status to hide it, deleting it, or excluding it with `SKIP LOCKED` is not resolution. This hold does not prohibit normal continuation past an examined, validated unexpired row under the selection contract: such a row is revisited on the next pass and does not establish complete coverage. Other tenants must retain service under the separately qualified admission/fair-turn policy, without increasing deployment allowance or adding an arbitrary retry policy. This document selects no fairness bound or retry schedule.

Schema, roles, restart behavior and diagnostic retention require their own design and measured proof before the table is executable.

## Next bounded step and fallback

The [inactive diagnostic read](../src/tenants/m365-audit-row-diagnostic.ts) now observes the current first known-unresolved row using the original scope and continuation. It returns only the scoped internal UUIDs, a six-decimal live observation timestamp and a boolean that the stored URI exceeds the selector's unchanged cap. It never returns the URI, content ID, source status, revision/deadline, hash, candidate, continuation or end-of-pass claim. The independently bounded JSON-text field has a fixed 1 KiB gate in the query and a defensive decoder check. The boolean cannot identify a page-serialization overflow, validate other source fields, decide expiry or attribute an earlier error to this row. Null means no current row under this predicate; unknown statuses are excluded and absence is never safe resolution.

Eight [scripted-transport tests](../src/tenants/m365-audit-row-diagnostic.test.ts) cover parameter capture, strict scoped response decoding, absent/changed observations, safe refusals and exact defensive byte limits. They execute no SQL. The query's scope/order/status projection, database clock, no-URI pretransport property, actual-adapter decoding and server-side byte gate remain unproved until registered disposable CI. A 1 KiB returned field is not a bound on scan work, detoasting, memory or total protocol overhead. The current schema has a scoped status/retry index and a primary ID index, not a dedicated proof of this ordered projection's plan or cost; no index or isolation change is made here.

Prepare its registered actual-adapter witness next: compare same-scope first-row identity with the selector's logical scan, preserve populated source/gap/state snapshots, exercise oversized and escaped first rows plus a valid tail, changed-row/new-lower-ID observations, wrong scope, null observations and asserted nondefault time settings. Compare server/client diagnostic bytes, inspect actual output for raw synthetic markers, and retain unknown-status/absence limits. No production integration may rely on the unexecuted query. Do not add a caller or advance a cursor when only diagnosis exists. Choose and qualify server-side exact-claim resolution separately, using the shared writer/owner contract rather than a timestamp-only shortcut. Keep the permanent-invalid-source gate open until its supported reconciliation route is concrete.

The local constant-coupling guard now binds the actual discovery and selector limits; it has no new hosted CI or Claude proof. Guarding duplicated expiry expressions remains separate. One passing clock test does not establish timing stability. The additional Claude adversarial workflow was incomplete and is not being claimed complete here. Protected main remains the fallback; no manual recovery or destructive schema rollback is proposed. Full independent source review, exact-head CI, normal protected merge, configured automatic release, actual health and authenticated canary remain required. Baseline and full SYNC are incomplete.
